# 해외여행자 분실·도난 사건 대응 서비스

해외여행 중 물품을 분실하거나 도난당한 여행자가 회원가입 없이 사건을 등록하고, AI의 도움을 받아 **사건 카드 생성 → 맞춤 해결 가이드 → 경찰서 현장 대응 → 보험·사후처리**까지 진행하는 서비스입니다.

현재 첫 구현 대상은 **일본을 여행 중인 한국인 사용자**입니다. 국가별 기관, 신고 절차, 보험·공식 자료를 분리해 이후 다른 국가로 확장할 수 있도록 설계합니다.

이 문서는 3주 동안 팀원 전원이 같은 기준으로 전체 기능을 구현하기 위한 프로젝트 온보딩·개발·협업 가이드입니다.

---

## 1. 3주 구현 목표와 전체 사용자 흐름

아래 기능은 우선순위에 따라 일부를 제외하는 후보 목록이 아니라 **모두 구현할 프로젝트 범위**입니다. 3주 일정은 기능을 줄이기 위한 기준이 아니라, 담당과 통합 순서를 정하기 위한 기준입니다.

1. 사용자가 회원가입 없이 새 사건을 시작합니다.
2. 사용자가 음성으로 분실·도난 상황을 설명합니다.
3. 음성이 텍스트로 변환되고 AI가 사건을 `분실` 또는 `도난`으로 분류합니다.
4. AI가 현재 위치·시간과 사건 카드의 빈 항목을 확인해 추가 질문합니다.
5. 사용자가 음성으로 채우지 못한 항목과 물품·여행자 세부 정보를 직접 입력합니다.
6. 사용자가 사건 카드를 확인·확정하고 비밀번호를 설정합니다.
7. 서버가 랜덤 사건번호를 발급합니다.
8. 사건 카드와 위치를 기반으로 우선순위가 있는 해결 가이드를 생성합니다.
9. 사용자는 가이드 순서를 드래그로 바꾸고 완료 상태를 기록합니다.
10. Google Maps API로 가까운 경찰서·파출소·대사관·관공서와 이동 정보를 확인합니다.
11. 경찰서 방문이 필요한 경우 신고 절차, 준비물, 상황 설명 스크립트와 신고서 초안을 확인합니다.
12. Agora 기반 실시간 음성 채널에서 양방향 통역을 사용하고, 상대방 안내의 의미와 다음 행동을 함께 설명받습니다.
13. 작성한 신고서를 촬영·업로드하면 문서 내용을 추출하고 누락 항목을 판별해 저장합니다.
14. 경찰서 신고 여부와 무관하게 카드사·통신사·렌터카사·보호자 연락 등 후속조치를 안내받습니다.
15. 사용자가 가입한 보험 정보를 입력하면 관련 약관·공식 자료를 RAG로 검색해 필요 서류와 보상 가능 범위를 안내합니다.
16. 여행 중인 국가에서만 발급할 수 있는 서류와 발급 절차를 확인합니다.
17. 경찰 신고 내용과 보험사 제출 내용을 비교해 사실관계의 불일치를 표시합니다.
18. 사용자는 웹 또는 모바일 앱에서 사건번호와 비밀번호로 기존 사건과 진행 상태를 다시 조회합니다.

## 2. 핵심 기능 요구사항

### 2.1 비로그인 사건 관리

- 회원가입과 계정 로그인을 사용하지 않습니다.
- 사건 카드를 확정할 때 추측하기 어려운 랜덤 사건번호를 발급합니다.
- 사용자가 설정한 비밀번호 원문은 저장하지 않고 안전한 해시만 저장합니다.
- 사건 조회 시 사건번호와 비밀번호를 모두 검증합니다.
- 사건번호 입력 반복 시도를 제한하고 인증 실패 응답에서 사건 존재 여부가 드러나지 않게 합니다.
- 사건별 삭제 예정일을 저장하고, 보관 기간이 지나면 연결된 DB 데이터와 S3 파일을 함께 삭제합니다.

### 2.2 음성 입력과 사건 카드 생성

- 웹과 모바일에서 음성 입력을 시작·중지하고 처리 상태를 확인할 수 있어야 합니다.
- 음성을 텍스트로 변환한 뒤 사건을 `분실` 또는 `도난`으로 분류합니다.
- AI는 확보한 정보와 비어 있는 필드를 구분하고 필요한 내용만 추가 질문합니다.
- 사용자는 AI가 추출한 내용을 직접 수정할 수 있습니다.
- AI 응답은 Zod 스키마 검증을 통과한 뒤 화면과 DB에서 사용합니다.
- AI 결과만으로 사건 카드를 확정하지 않고 최종 사용자 확인을 거칩니다.

#### 사건 카드 항목

| 구분 | 항목 |
|---|---|
| 사건 기본 정보 | 사건 유형, 현재 위치, 현재 날짜·시간, 사건 발생 추정 장소·시간 |
| 물품 정보 | 분실·도난 물품, 수량, 색상·브랜드·모델 등 특징, 마지막으로 본 위치 |
| 도난 추가 정보 | 목격자 유무·진술, 범인 인상착의 |
| 여행자 정보 | 체류기간, 체류 숙소, 여권번호 인지 여부 |
| 처리 상태 | 작성 중, 사용자 확인, 확정, 가이드 진행, 경찰 신고, 사후처리, 완료 |

`여권번호 인지 여부`와 실제 `여권번호`는 별도 데이터입니다. 실제 번호가 필요한 화면에서는 저장 목적을 알리고 입력받으며, 저장 시 암호화하고 화면에는 마스킹해 표시합니다.

### 2.3 해결 가이드

- 사건 카드와 공식 절차 자료를 바탕으로 해야 할 일을 순서가 있는 리스트로 제공합니다.
- 카드·휴대전화·여권·렌터카 키 등 물품의 위험도에 따라 긴급 조치를 먼저 표시합니다.
- 각 단계에는 `해야 할 일`, `필요한 이유`, `준비물`, `연락처·기관`, `완료 여부`를 포함합니다.
- 경찰 신고가 필요한지 설명하고 경찰서 외 대안이 있으면 함께 제시합니다.
- 사용자가 가이드 순서를 드래그로 조정하면 변경된 순서를 DB에 저장합니다.
- 완료한 단계와 다음 행동을 웹·모바일에서 동일하게 확인할 수 있어야 합니다.

### 2.4 위치 기반 기관 검색

- 사용자 동의를 받은 현재 위치 또는 직접 입력한 위치를 사용합니다.
- Google Maps API로 가까운 경찰서·파출소·대사관·관공서를 검색합니다.
- 기관명, 주소, 거리, 영업·운영 정보, 지도 위치와 이동 경로를 제공합니다.
- 위치 권한이 없거나 검색 결과가 없을 때 직접 지역을 입력할 수 있어야 합니다.
- 검색된 외부 정보는 최신성을 보장할 수 없음을 표시하고 공식 연락처 확인 경로를 함께 제공합니다.

### 2.5 경찰서 현장 대응과 양방향 통역

- 방문 전 필요한 준비물, 예상 신고 절차, 주의사항을 안내합니다.
- 사건 카드를 기반으로 한국어·일본어 상황 설명 스크립트와 신고서 초안을 생성합니다.
- Agora는 웹·모바일과 현장 상대방 사이의 실시간 음성 채널과 세션을 담당합니다.
- OpenAI는 전달된 음성의 텍스트 변환, 번역, 사건 문맥에 맞는 설명 생성을 담당합니다.
- 양쪽 발화를 원문·번역문으로 구분해 표시하고, 경찰이 안내한 절차의 의미와 사용자의 다음 행동을 덧붙입니다.
- 통역 결과가 법적 효력을 가진 전문 통역을 대체하지 않는다는 안내를 표시합니다.
- 세션 종료 시 필요한 대화 요약만 사건 기록에 저장하고, 원본 음성 보관 여부와 기간을 사용자에게 안내합니다.

### 2.6 신고서 초안·업로드·누락 판별

- 사건 카드와 현장 대화 내용을 기반으로 신고서 초안을 생성합니다.
- 사용자가 사진 또는 PDF를 업로드하면 S3 비공개 버킷에 저장합니다.
- 업로드한 문서에서 텍스트와 항목을 추출하고, 사건 유형별 필수 항목과 대조합니다.
- 이름, 사건 일시·장소, 물품, 접수번호, 기관 정보, 서명 등 누락 가능 항목을 표시합니다.
- 자동 판별 결과는 확정 판단이 아니라 확인이 필요한 항목으로 제시합니다.
- DB에는 공개 URL이 아닌 S3 객체 키와 분석 결과를 저장합니다.

### 2.7 보험 RAG와 사후처리

- 카드사, 통신사, 렌터카사, 보호자 연락 등 사건별 후속조치를 먼저 안내합니다.
- 사용자가 보험사·상품명·가입 정보를 입력하거나 관련 문서를 업로드할 수 있어야 합니다.
- 공식 보험 약관, 기관 절차, 제출 서류 자료를 수집하고 출처·국가·시행일·버전을 함께 저장합니다.
- 문서를 청크로 나눠 임베딩하고 PostgreSQL의 pgvector에서 관련 근거를 검색합니다.
- 검색 근거를 OpenAI에 전달해 필요 서류, 보상 가능 범위, 제출 순서와 주의사항을 생성합니다.
- 답변에는 사용한 자료명과 근거 위치를 표시하고, 근거가 부족하면 추정해서 확정하지 않습니다.
- 여행 국가에서만 발급 가능한 서류와 발급 기관·절차를 별도로 안내합니다.
- 경찰 신고서, 사건 카드, 보험사 제출 초안의 날짜·장소·물품·사건 설명을 항목별로 비교하고 불일치를 표시합니다.

### 2.8 웹·모바일 공통 동작

- Next.js 웹과 React Native·Expo 모바일 앱은 같은 API와 공통 Zod 스키마를 사용합니다.
- 사건 생성, 사건 조회, 사건 카드 확인, 가이드, 기관 검색, 현장 통역, 문서 업로드, 사후처리 화면을 두 클라이언트에서 제공합니다.
- 카메라·마이크·위치 권한 거부, 네트워크 단절, 업로드 실패, AI 응답 실패 상태를 각각 처리합니다.
- 처리 중 중복 제출을 방지하고 재시도 가능한 작업을 사용자에게 구분해 보여줍니다.

## 3. 데이터 저장 및 보호 원칙

이 서비스는 사건 해결을 위해 사건 정보, 위치, 숙소, 보험 정보, 음성, 신고 문서 등을 저장합니다. 따라서 사용자에게 **“개인정보를 저장하지 않는다”라고 안내하지 않습니다.** 대신 저장 목적, 저장 항목, 보관 기간, 접근 방법과 삭제 시점을 명확히 고지합니다.

### 저장 데이터

| 저장 위치 | 데이터 예시 |
|---|---|
| PostgreSQL | 사건번호, 비밀번호 해시, 사건 유형, 위치·시간, 물품 특징, 여행 정보, 가이드 진행 상태, 보험 정보, 문서 분석 결과, S3 객체 키 |
| PostgreSQL + pgvector | 공식 절차·보험 자료의 청크, 임베딩, 출처·버전 메타데이터 |
| AWS S3 비공개 버킷 | 음성, 신고서 사진, PDF, 보험 관련 문서 |
| 저장하지 않는 값 | 비밀번호 원문, API 키, AWS 자격 증명, 처리에 불필요한 민감정보 |

### 필수 보호 규칙

- 숙소 상세주소, 여권번호, 증권번호, 문서번호 등은 화면에 마스킹해 표시합니다.
- 복원이 필요한 민감정보는 애플리케이션 계층에서 암호화한 뒤 DB에 저장합니다.
- 마스킹되지 않은 민감정보를 애플리케이션·Docker·Nginx 로그에 남기지 않습니다.
- 비밀번호는 Argon2id 또는 bcrypt로 솔트 해시합니다.
- S3 버킷의 공개 접근을 차단하고, 짧은 만료시간의 presigned URL로만 파일에 접근합니다.
- PostgreSQL의 5432 포트는 인터넷에 공개하지 않습니다.
- 사건번호는 순차 번호가 아니라 충분히 긴 암호학적 랜덤 값으로 생성합니다.
- 사건 조회, 비밀번호 검증, 파일 업로드, Agora 토큰 발급 API에는 요청 횟수 제한을 적용합니다.
- 운영 비밀값과 `.env` 파일은 Git에 커밋하지 않습니다.
- `DATA_RETENTION_DAYS`와 사용자 안내 문구의 보관 기간을 같은 값으로 유지합니다.
- 자동 삭제 Worker는 만료된 사건의 S3 객체 삭제 성공 여부를 확인한 뒤 DB 삭제 상태를 기록합니다.
- 개발·시연에는 가짜 데이터만 사용하고 실제 여권번호, 숙소 주소, 보험증권을 테스트 데이터로 사용하지 않습니다.

> 마스킹은 화면 노출을 줄이는 방법이고 저장 데이터 자체를 보호하는 방법은 아닙니다. 저장 시 암호화, 접근 통제, 로그 제외, 자동 삭제를 함께 적용합니다.

## 4. 확정 기술 스택

| 영역 | 기술 | 용도 |
|---|---|---|
| 공통 언어 | TypeScript | 웹·모바일·백엔드·Worker 언어 통일 |
| 웹 | Next.js + React | 브라우저용 서비스 화면 |
| 모바일 | React Native + Expo | Android·iOS 앱 |
| 모바일 라우팅 | Expo Router | 파일 기반 앱 화면 이동 |
| 백엔드 API | Next.js Route Handlers | 사건·가이드·문서·토큰 API |
| 검증 | Zod | API 요청·응답과 AI 결과 형식 검증 |
| ORM | Prisma | TypeScript와 PostgreSQL 연결 |
| 메인 DB | PostgreSQL 1개 | 사건·물품·가이드·문서·진행 상태 저장 |
| 자료 검색 | PostgreSQL + pgvector | 공식 절차·보험 자료 RAG 검색 |
| AI | OpenAI | 음성 처리, 사건 분류, 추가 질문, 가이드, 번역, 문서 추출·비교 |
| 음성·통역 | Agora | 실시간 음성 채널과 양방향 통역 세션 |
| 위치·기관 검색 | Google Maps API | 가까운 기관 검색과 경로 안내 |
| 파일 저장 | AWS S3 비공개 버킷 | 음성·사진·PDF·신고서 저장 |
| 서버 | AWS EC2 Ubuntu | 웹·API·Worker·DB 실행 |
| 컨테이너 | Docker | 실행 환경과 프로그램 격리 |
| 통합 실행 | Docker Compose | 여러 컨테이너 일괄 실행 |
| 프록시·HTTPS | Nginx + Certbot | 요청 전달과 Let's Encrypt 인증서 발급·갱신 |
| 협업 | GitHub Organization | 저장소·Issue·PR 관리 |
| 패키지 관리 | pnpm Workspace | 모노레포 패키지 관리 |

기술 변경이나 대체는 개인 판단으로 진행하지 않고 Issue에서 이유와 영향을 공유한 뒤 팀 합의로 결정합니다.

> Nginx가 인증서를 스스로 자동 발급하는 것은 아닙니다. Nginx가 HTTP·HTTPS 요청을 전달하고 Certbot이 인증서를 발급·갱신합니다.

## 5. 시스템 구성과 데이터 흐름

```text
Next.js 웹                 React Native + Expo 앱
    |                              |
    +----------- HTTPS ------------+
                   |
            Nginx + Certbot
                   |
        Next.js Route Handlers API
          |        |        |       \
          |        |        |        +-- Google Maps API
          |        |        +----------- Agora
          |        +-------------------- AWS S3
          +----------------------------- PostgreSQL + pgvector
                   |
                AI Worker
                   |
                 OpenAI
```

### 요청 흐름

1. 웹·모바일은 HTTPS로 Next.js Route Handlers를 호출합니다.
2. API는 Zod로 입력을 검증하고 Prisma를 통해 PostgreSQL을 읽고 씁니다.
3. 짧은 AI 작업은 API가 처리 결과를 기다리고, 문서 분석·RAG 적재·자동 삭제 등 긴 작업은 DB의 작업 테이블에 등록합니다.
4. AI Worker는 PostgreSQL 작업 테이블을 조회해 작업을 수행하고 상태와 결과를 다시 저장합니다.
5. 파일 원본은 S3에 저장하고 PostgreSQL에는 객체 키와 메타데이터만 저장합니다.
6. Agora 토큰은 서버에서 발급하며 App Certificate 같은 비밀값을 클라이언트에 전달하지 않습니다.
7. Google Maps 브라우저용 키와 서버용 키는 용도·도메인·API별로 제한합니다.

### Docker Compose 서비스

- `nginx`: HTTP·HTTPS 요청을 `web`으로 전달
- `certbot`: 인증서 발급·갱신
- `web`: Next.js 웹과 Route Handlers API
- `ai-worker`: OpenAI, 문서 분석, RAG 적재, 자동 삭제 작업
- `postgres`: PostgreSQL + pgvector

OpenAI, Agora, Google Maps API와 AWS S3는 Docker Compose 내부 서비스가 아니라 외부 서비스입니다. Expo 앱은 EC2 컨테이너에서 실행하지 않고 배포된 API에 접속합니다.

## 8. 개발 환경 시작하기

### 8.1 저장소 클론

```bash
git clone https://github.com/<organization>/<repository>.git
cd <repository>
```

`<organization>`과 `<repository>`는 설명을 위한 자리표시자입니다. 실제 저장소 주소와 클론 후 생성된 폴더 이름으로 바꿔야 합니다.

예를 들어 저장소 주소가 `https://github.com/team-name/travel-guard.git`이라면 다음과 같이 실행합니다.

```bash
git clone https://github.com/team-name/travel-guard.git
cd travel-guard
```

기존 문서의 `cd project-root`는 `project-root`라는 설정을 먼저 만들라는 뜻이 아닙니다. 단지 **클론한 프로젝트의 최상위 폴더로 이동하라**는 예시 표현입니다. 저장소 이름이 정해지기 전이라 임시 이름을 쓴 것이므로 실제 README에는 저장소 폴더명을 적습니다.

### 8.2 최초 실행

```bash
pnpm install
cp .env.example .env
docker compose -f infra/docker-compose.yml up -d postgres
pnpm --filter @project/db prisma migrate dev
pnpm --filter web dev
pnpm --filter mobile start
pnpm --filter worker dev
```

위 `--filter` 이름은 각 `package.json`의 실제 `name`과 `scripts`를 만든 뒤 정확한 값으로 맞춥니다. 문서에 존재하지 않는 명령을 확정 명령처럼 남기지 않습니다.

### 8.3 환경 변수 예시

```dotenv
DATABASE_URL=
OPENAI_API_KEY=
AGORA_APP_ID=
AGORA_APP_CERTIFICATE=
NEXT_PUBLIC_GOOGLE_MAPS_BROWSER_KEY=
GOOGLE_MAPS_SERVER_API_KEY=
AWS_REGION=ap-northeast-1
AWS_S3_BUCKET=
AWS_ACCESS_KEY_ID=
AWS_SECRET_ACCESS_KEY=
DATA_ENCRYPTION_KEY=

```

- `.env.example`에는 변수 이름과 설명만 적고 실제 비밀값은 넣지 않습니다.
- EC2에서는 가능한 경우 AWS 액세스 키를 파일에 저장하지 않고 인스턴스 역할을 사용합니다.
- `NEXT_PUBLIC_`이 붙은 값은 클라이언트에 노출될 수 있으므로 Google Cloud Console에서 허용 도메인과 API를 제한합니다.

- `docs/<issue-number>-<short-name>`: 문서 수정

예시: `feature/12-case-card`, `fix/31-s3-upload`

### Issue → PR 흐름

1. 작업 전에 Issue를 만들고 담당자, 완료 조건, 관련 화면·API를 적습니다.
2. 최신 `develop`에서 작업 브랜치를 만듭니다.
3. 기능 단위로 커밋하고 원격 저장소에 push합니다.
4. `develop`을 대상으로 PR을 만들고 변경 이유, 실행 화면, 테스트 방법을 적습니다.
5. 최소 1명의 승인과 필수 CI 통과 후 merge합니다.
6. `main`에는 팀이 확인한 배포 버전만 PR로 merge합니다.

### GitHub 브랜치 보호 권장값

- `main`, `develop` 직접 push 금지
- PR을 통해서만 merge 허용
- 최소 승인 1명 필수
- 새 커밋이 추가되면 기존 승인 무효화
- 미해결 리뷰 대화가 있으면 merge 금지
- 필수 CI가 성공해야 merge 허용
- force push와 branch deletion 금지

### PR 체크리스트

- [ ] 연결된 Issue와 완료 조건이 있는가?
- [ ] 로컬에서 직접 실행했는가?
- [ ] 웹·모바일·API 중 영향받는 영역을 확인했는가?
- [ ] 공통 타입 또는 API 변경을 `packages/shared`와 문서에 반영했는가?
- [ ] 실제 개인정보, `.env`, API 키가 포함되지 않았는가?
- [ ] 화면 변경이면 스크린샷 또는 짧은 영상을 첨부했는가?
- [ ] DB 변경이면 새 Prisma migration을 포함했는가?
- [ ] 성공·실패·권한 거부·네트워크 오류 중 관련 상태를 테스트했는가?

### 커밋 메시지

```text
feat: 사건 카드 생성 API 추가
fix: 사건 조회 비밀번호 검증 오류 수정
docs: 로컬 실행 방법 수정
refactor: 가이드 생성 로직 분리
test: 문서 누락 판별 테스트 추가
chore: 의존성 업데이트
```

### 금지 사항

- 공유 DB 스키마, API 계약, 공통 타입을 알리지 않고 변경하지 않습니다.
- 이미 공유·적용된 Prisma migration을 수정하거나 삭제하지 않습니다.
- `.env`, AWS 키, OpenAI 키, Agora App Certificate, 실제 개인정보를 커밋하지 않습니다.
- 리뷰 없이 `main` 또는 `develop`에 직접 push하지 않습니다.
- 다른 담당자의 파일을 대규모로 수정해야 하면 먼저 Issue나 팀 채널에 범위를 공유합니다.

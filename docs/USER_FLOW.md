# 표기 규칙 

- `UI`: 프론트엔드에서 고정 구현
- `USER`: 사용자가 입력하는 정보
- `AI`: AI가 분석하거나 생성하는 정보
- `API`: 서버·DB에서 전달받는 정보
- `STATE`: 로딩·오류·완료 상태에 따라 달라지는 영역

# S02. 음성 입력 화면

## 화면 구성

| 화면 요소 | 구분 | 위치 | 내용 |
|-----------|------|------|------|
| 뒤로가기 버튼 | `UI` | 화면 좌측 상단 | 이전 화면으로 이동하는 화살표 버튼 |
| 신고 유형 제목 | `UI` | 화면 상단 중앙 | `분실·도난 신고` 문구 표시 |
| 메인 안내 문구 | `UI` | 헤더 하단 | `무슨 일이 있었는지 알려주세요` 문구 표시 |
| 화면 설명 문구 | `UI` | 메인 안내 문구 하단 | 사건 경위를 말하면 신고서 초안을 자동으로 작성한다는 설명 표시 |
| 음성 녹음 버튼 | `UI` | 화면 중앙 | 음성 녹음을 시작하는 마이크 버튼 |
| 녹음 상태 | `STATE` | 음성 녹음 버튼 하단 | 녹음 중일 때 빨간 표시점과 `녹음 중...` 문구 표시 |
| 녹음 시간 | `STATE` | 녹음 상태 하단 | 현재 음성 녹음 경과 시간을 `00:17` 형식으로 표시 |
| 음성 인식 내용 | `AI` | 녹음 시간 하단 | 사용자 음성을 실시간으로 변환한 텍스트 표시 |
| 녹음 중지 버튼 | `UI` | 음성 인식 내용 하단 | 진행 중인 음성 녹음을 종료하는 주요 버튼 |
| 다시 녹음 버튼 | `UI` | 녹음 중지 버튼 하단 좌측 | 기존 녹음과 인식 내용을 초기화하고 다시 녹음하는 버튼 |
| 텍스트 입력 버튼 | `UI` | 녹음 중지 버튼 하단 우측 | 사건 경위를 직접 입력하는 방식으로 전환하는 버튼 |
| 현재 위치 | `API` | 화면 하단 정보 영역 좌측 | 기기에서 확인한 사용자의 현재 위치 표시 |
| 현지 시간 | `API` | 화면 하단 정보 영역 우측 | 현재 위치를 기준으로 한 현지 시간 표시 |
| 오프라인 안내 | `UI` | 화면 최하단 | 오프라인 환경에서도 음성 인식이 가능하다는 안내 표시 |

## 화면 이동

| 선택 요소 | 조건 | 결과 |
|-----------|------|------|
| 뒤로가기 버튼 | 항상 | S01 홈 화면으로 이동 |
| 음성 녹음 버튼 | 녹음 대기 상태 | 음성 녹음을 시작하고 녹음 상태와 경과 시간 표시 |
| 녹음 중지 버튼 | 인식된 음성 내용 있음 | 녹음을 종료하고 S03 녹음내용 확인 화면으로 이동 |
| 녹음 중지 버튼 | 인식된 음성 내용 없음 | S02 화면을 유지하고 사건 경위 입력 안내 표시 |
| 다시 녹음 버튼 | 항상 | 기존 녹음을 일시 정지함 |
| 텍스트 입력 버튼 | 항상 | 음성 녹음을 중지하고 직접 입력 모드로 전환 |


# S03. 녹음내용 확인 화면

## 화면 구성

| 화면 요소 | 구분 | 위치 | 내용 |
|-----------|------|------|------|
| 뒤로가기 버튼 | `UI` | 화면 좌측 상단 | 이전 화면으로 이동하는 화살표 버튼 |
| 화면 제목 | `UI` | 화면 상단 중앙 | `말씀해주신 내용이 맞나요?` 문구 표시 |
| 진행 표시줄 | `STATE` | 헤더 하단 | 전체 과정에서 현재 진행 정도 표시 |
| 녹음된 내용 제목 | `UI` | 진행 표시줄 하단 | `녹음된 내용` 문구 표시 |
| 녹음된 내용 | `AI` | 녹음된 내용 제목 하단 | S02에서 사용자 음성을 텍스트로 변환한 사건 경위 표시 |
| 내용 수정 버튼 | `UI` | 녹음된 내용 영역 우측 하단 | 연필 아이콘을 눌러 녹음된 사건 경위를 직접 수정하는 버튼 |
| 수정된 사건 내용 | `USER` | 녹음된 내용 영역 | 사용자가 직접 수정한 사건 경위 표시 및 저장 |
| 다시 녹음하기 버튼 | `UI` | 녹음된 내용 하단 좌측 | 사건 경위를 음성으로 다시 입력하는 버튼 |
| 현재 위치 수정 버튼 | `UI` | 다시 녹음하기 버튼 우측 | 자동 확인된 사건 발생 위치를 수정하는 버튼 |
| 발생 시간 수정 버튼 | `UI` | 수정 버튼 영역 하단 | 자동 확인된 사건 발생 시간을 수정하는 버튼 |
| 수정된 현재 위치 | `USER` | 위치 수정 영역 | 사용자가 직접 수정한 사건 발생 위치 저장 |
| 수정된 발생 시간 | `USER` | 시간 수정 영역 | 사용자가 직접 수정한 사건 발생 시간 저장 |
| AI 분석 안내 | `UI` | 수정 버튼 영역 하단 | 작성된 내용을 바탕으로 일본 경찰서 제출용 신고서 초안을 구성한다는 안내 표시 |
| 예상 신고서 유형 | `AI` | AI 분석 안내 영역 | 사건 내용을 분석해 예상되는 신고서 유형을 `분실물 센터 접수증` 등의 형태로 표시 |
| 이 내용으로 분석하기 버튼 | `UI` | 화면 하단 | 확인한 사건 내용으로 AI 분석을 시작하는 주요 버튼 |
| 분석 진행 상태 | `STATE` | 분석하기 버튼 영역 | 분석 요청의 대기·진행·완료·오류 상태 표시 |

| 선택 요소 | 조건 | 결과 |

| 내용 수정 버튼 | 항상 | S03 화면에서 사건 경위 직접 수정 모드로 전환 |
| 다시 녹음하기 버튼 | 항상 | 기존 녹음과 인식 내용을 초기화하고 S02 음성 입력 화면으로 이동 |
| 현재 위치 수정 버튼 | 항상 | S03 화면에서 사건 발생 위치 수정 영역 표시 |
| 발생 시간 수정 버튼 | 항상 | S03 화면에서 사건 발생 시간 수정 영역 표시 |
| 이 내용으로 분석하기 버튼 | 사건 내용 있음 | 입력 내용을 분석하고 S04 추가 질문 화면으로 이동 |
| 이 내용으로 분석하기 버튼 | 사건 내용 없음 | S03 화면을 유지하고 사건 내용 입력 안내 표시 |
| 이 내용으로 분석하기 버튼 | 분석 실패 | S03 화면을 유지하고 재시도 안내 표시 |


# S04. 추가 질문 화면

| 화면 요소 | 구분 | 위치 | 내용 |

| 신고 유형 제목 | `UI` | 화면 상단 중앙 | `분실·도난 신고` 문구 표시 |
| 진행 표시줄 | `STATE` | 헤더 하단 | 전체 과정에서 현재 진행 정도 표시 |

| 추가 질문 답변 칸 | `USER` | 현재 질문 하단 | 추가 질문에 대한 답변 작성|
| 이 내용으로 분석하기 버튼 | `UI` | 화면 하단 | 마지막 질문의 답변을 저장하고 추가 질문 단계를 완료하는 주요 버튼 |

# S05. 사건카드 내용 확정 화면

## 화면 구성

| 화면 요소 | 구분 | 위치 | 내용 |
|-----------|------|------|------|
| 뒤로가기 버튼 | `UI` | 화면 좌측 상단 | 이전 화면으로 이동하는 화살표 버튼 |
| 신고 유형 제목 | `UI` | 화면 상단 중앙 | `분실·도난 신고` 문구 표시 |
| 메인 안내 문구 | `UI` | 헤더 하단 | `사건 내용을 이렇게 정리했어요` 문구 표시 |
| 사건 유형 | `AI` | 메인 안내 문구 하단 | 분석한 사건 유형을 `분실` 또는 `도난`으로 표시 |
| 사건 유형 수정 버튼 | `UI` | 사건 유형 영역 우측 | AI가 분류한 사건 유형을 사용자가 수정하는 버튼 |
| 분실 물품 | `AI` | 사건 유형 하단 | 분석한 분실 물품을 `여권`, `신용카드` 등의 태그로 표시 |
| 분실 물품 수정 버튼 | `UI` | 분실 물품 영역 우측 상단 | 분실 물품을 추가·삭제·수정하는 버튼 |

| 발생 장소 | `AI` | 사건 정보 영역 우측 | 확인된 국가·도시와 상세 장소를 표시 |
| 긴급 물품 여부 | `AI` | 사건 정보 하단 좌측 | 여권 등 긴급 대응이 필요한 물품의 포함 여부를 강조 표시 |
| 위험도 | `AI` | 사건 정보 하단 우측 | 사건 내용을 바탕으로 분석한 위험 수준을 표시 |

## 기능 규칙

- 사건번호는 S05 저장 응답을 사용하며 비밀번호는 생성하거나 fixture에 저장하지 않는다.
- 내부 사건번호 값은 서버 스키마 형식을 유지하고 화면에서만 읽기 쉬운 구분 기호를 추가한다.
- 비밀번호와 비밀번호 확인값은 S06 Screen 로컬 상태로만 관리하고 Context·URL·로그에 넣지 않는다.
- 비밀번호는 공유 `casePasswordSchema`를 기준으로 검증한다.
- 비밀번호 설정 중 중복 요청을 차단한다.
- 설정 실패 시 입력값을 유지하고 다시 시도할 수 있다.
- 설정 성공 후 비밀번호 입력값을 메모리에서 지우고 완료 상태를 표시한다.
